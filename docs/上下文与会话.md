# 上下文与会话

Vivlos 以 Session（会话）保存连续对话，并在每次请求前把 History（对话历史）、Memory（记忆）、Todo（待办）和压缩摘要组合成模型上下文。

## Session 生命周期

新 Session 初始为 pending（待激活）状态，只在内存中拥有 ID 和预计算路径。第一次发送消息时才激活并创建目录与 `history.jsonl`。

Session 支持：

- 新建与切换。
- 删除与重命名。
- 首次对话后异步生成标题。
- 从 JSONL（逐行 JSON 文件）恢复 user、assistant 和 toolResult 消息。

切换 Session 会重置 Prompt（提示词）缓存、Memory Runtime（记忆运行时）、压缩状态和 Skill（技能）加载状态。

## History JSONL

`history.jsonl` 第一行是带版本、Session ID、名称和时间的 Header（文件头），后续每行是一条消息或压缩记录。

消息以追加方式保存，角色仅包括：

- `user`（用户消息）
- `assistant`（模型回复）
- `toolResult`（工具结果）

重命名 Session 时会重写 Header，其余正常对话以追加为主。

## 请求上下文

一次模型调用的上下文包含：

- 当前冻结的 System Prompt（系统提示词）。
- SessionManager（会话管理器）中的有效历史消息。
- 本次用户输入。
- 当前可用 Tools（工具）。
- 可选的临时 Todo Hint（待办提示）。

临时 Hint 可以参与当前请求与重试，但通过稳定消息 ID 排除在持久化历史之外。

## Prompt 缓存

System Prompt 在 Session 内缓存，减少每个推理步骤的重复构建。以下事件会使缓存失效：

- 当前 Session 的 L1 Memory 发生变化。
- 上下文压缩产生新摘要。
- 切换或新建 Session。

环境时间属于 Prompt 快照，只在重新构建时更新。

## 自动压缩

每次 User Turn（对话轮次）开始前，Compactor（压缩器）根据最近一次模型用量判断上下文占用。达到配置阈值后执行：

1. Cheap Prune（廉价剪枝）：截断过长的工具结果、大型工具参数并去除重复结果。
2. 分段：保留少量开头消息和最近的尾部消息。
3. 摘要：把中间历史压缩成结构化摘要。
4. 更新 Prompt 中的 `compacted_history` 段落。

摘要重点保留目标、约束、已完成工作、进行中工作、关键决策和下一步。

旧摘要会作为不可信用户数据交给 Summarizer（摘要模型），不能单独证明历史操作已完成。摘要失败时会退化为消息预览，避免完全丢失上下文。

## 手动压缩

`/compact` 会跳过自动触发阈值，直接尝试压缩当前会话。空会话、过短会话或没有可压缩中段时会拒绝操作。

## 压缩边界

当前压缩主要影响运行中的内存上下文：

- 原始 JSONL 消息不会被删除。
- 压缩记录会写入 JSONL 作为审计。
- 当前恢复流程仍主要加载原始消息，尚未完整恢复压缩后的内存快照。

因此，切换 Session 或重启后可能重新加载完整原始历史，而不是继续使用之前的摘要。这是当前实现限制，压缩并不会永久改写会话记录。

## Session 本地数据

```text
.vivlos/sessions/<session-id>/
├── history.jsonl
├── memory.md
├── user.md
├── memory-events.jsonl
├── memory-cursor.json
└── todos.json
```

其中 History 是对话状态源，Markdown 文件是 L1 Memory 状态源，`todos.json` 是当前 Todo 状态源。Memory Event Log（记忆操作日志）是尽力而为的记录，不替代 Markdown。
