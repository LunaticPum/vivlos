# 上下文与会话

Vivlos 以 Session 保存连续对话，并在每次请求前把 History、Memory、Todo 和压缩摘要组合成模型上下文。

## Session 生命周期

新 Session 初始为 pending，只在内存中拥有 ID 和预计算路径。第一次发送消息时才激活并创建目录与 `history.jsonl`。

Session 支持：

- 新建与切换。
- 删除与重命名。
- 首次对话后异步生成标题。
- 从 JSONL 恢复 user、assistant 和 toolResult。

切换 Session 会重置 Prompt 缓存、Memory Runtime、压缩状态和 Skill 加载状态。

## History JSONL

`history.jsonl` 第一行是带版本、Session ID、名称和时间的 Header，后续每行是 Message 或 Compaction Entry。

消息以追加方式保存，角色仅包括：

- `user`
- `assistant`
- `toolResult`

重命名 Session 时会重写 Header，其余正常对话以 append 为主。

## 请求上下文

一次模型调用的 Context 包含：

- 当前冻结的 System Prompt。
- SessionManager 中的有效历史消息。
- 本次用户输入。
- 当前可用 Tools。
- 可选的临时 Todo Hint。

临时 Hint 可以参与当前请求与 retry，但通过稳定 Message ID 排除在持久化 History 之外。

## Prompt 缓存

System Prompt 在 Session 内缓存，减少每个 ReAct step 的重复构建。以下事件会使缓存失效：

- 当前 Session 的 L1 Memory 发生变化。
- 上下文压缩产生新摘要。
- 切换或新建 Session。

环境时间属于 Prompt 快照，只在重新构建时更新。

## 自动压缩

每次 User Turn 开始前，Compactor 根据最近 assistant usage 判断上下文占用。达到配置阈值后执行：

1. Cheap Prune：截断过长 Tool Result、大型 Tool 参数并去除重复结果。
2. 分段：保留少量开头消息和最近 Tail。
3. 摘要：把中间历史压缩成结构化 Summary。
4. 更新 Prompt 中的 `compacted_history`。

摘要重点保留目标、约束、已完成工作、进行中工作、关键决策和下一步。

旧摘要会作为不可信用户数据交给 Summarizer，不能单独证明历史操作已完成。摘要失败时会退化为消息预览，避免完全丢失上下文。

## 手动压缩

`/compact` 会跳过自动触发阈值，直接尝试压缩当前会话。空会话、过短会话或没有可压缩中段时会拒绝操作。

## 压缩边界

当前压缩主要影响运行中的内存 Context：

- 原始 JSONL 消息不会被删除。
- Compaction Entry 会写入 JSONL 作为记录。
- 当前恢复流程仍主要加载原始 Message，尚未完整恢复压缩后的内存快照。

因此，切换 Session 或重启后可能重新加载完整原始历史，而不是继续使用之前的摘要。这是当前实现限制，不应把压缩理解为永久改写会话记录。

## Session 本地数据

```text
.vivlos/sessions/<session-id>/
├── history.jsonl
├── memory.md
├── user.md
├── memory-events.jsonl
├── memory-cursor.json
└── todos.json
```

其中 History 是对话状态源，Markdown 是 L1 Memory 状态源，`todos.json` 是当前 Todo 状态源。Memory Event Log 是 best-effort 记录，不替代 Markdown。
