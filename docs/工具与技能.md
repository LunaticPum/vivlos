# 工具与技能

Tool（工具）提供可执行能力，Skill（技能）提供按需加载的专业操作指引。两者职责不同：Skill 本身不执行任务，最终操作仍由 Tool 完成。

## Tool 分类

### Builtin Tools（内置工具）

| Tool | 作用 |
| --- | --- |
| `read` | 读取文件 |
| `write` | 新建或完整写入文件 |
| `bash` | 执行 Shell（命令行）命令 |
| `ls` | 列出目录 |
| `grep` | 搜索文件内容 |
| `find` | 查找文件 |
| `skill` | 加载 Skill 正文或 Reference（参考资料） |

### Advanced Tools（高级工具）

| Tool | 作用 |
| --- | --- |
| `memory` | 管理当前 Session（会话）的 L1 Memory（会话记忆） |
| `session_search` | 检索跨 Session 的历史对话片段（L2） |
| `todo_*` | 管理当前 Session 的 Todo List（待办清单） |
| `task` | 管理跨 Session Task（长期任务） |
| `offer_choice` | 等待用户选择 |

Tool Registry（工具注册表）按名称注册工具。同名 Tool 后注册时覆盖前一个定义，最终列表注入 Agent 上下文。

## Tool Schema（参数结构）

Tool 使用 TypeBox（类型描述库）描述参数：

- 静态结构由 `Type.Object`、`Type.Array`、`Type.Union` 等表达。
- `additionalProperties: false` 防止模型传入未声明字段。
- 动态业务约束在 Tool Adapter（工具适配层）或领域层检查。
- Schema 描述只说明参数含义，不承载整套工作流文档。

## 参数准备

`prepareArguments`（参数预处理）发生在 Schema 校验之前，只用于窄范围兼容：

- Skill Tool 丢弃部分模型误传的无关字段。
- Todo 将合法的字符串化 Item 数组恢复成真实数组。

损坏参数不使用正则或宽松解析器猜测修复。准备或校验失败会生成明确的 Tool Error（工具错误），由模型在下一轮自行修正。

## 执行模式

pi 支持并行和顺序执行：

- 默认 Tool 可以与同批独立调用并行。
- 任一 Tool 声明 `sequential`（顺序执行）时，整批按顺序执行。
- Todo 使用顺序执行，避免同一 List 的并发写入。
- Offer Choice 使用顺序执行，避免多个交互等待重叠。

多个独立操作会在同一个模型回复中发出；存在结果依赖时才拆成多个推理步骤。

## 结果与错误

成功的 Tool 返回：

- `content`：提供给模型的文本或结构化结果。
- `details`：提供给界面、事件和日志的结构化信息。
- 可选 `terminate`（终止标记）：整批结果都要求终止时，不再请求下一轮模型。

执行失败时抛出 `ToolError`，pi 会生成 `isError: true` 的 Tool Result（工具结果）并回灌模型。

只有成功的 Tool Result 才能作为"操作已完成"的依据。Thinking（思考过程）、普通文本或错误内容都不能证明写盘、命令或状态更新成功。

## Bash Tool

Bash 在 Windows 优先使用 Git Bash，支持：

- 超时控制。
- AbortSignal（中止信号）。
- 进程树终止。
- stdout/stderr（标准输出/错误输出）上限。
- 通配权限规则。

权限规则位于 `.vivlos/config.json`，按配置顺序匹配，并以最后命中的规则为准。

> [!WARNING]
> Bash 不是 Sandbox（沙箱），当前没有逐次确认界面。宽泛的后置 `allow` 规则可能覆盖前面的 `deny`，配置时需要仔细检查规则顺序。

文件工具同样允许绝对路径，当前没有统一的工作目录范围限制。

## Skill 发现

启动时递归扫描内置和扩展目录下的 `SKILL.md`。YAML Frontmatter（文档头部元数据）至少包含：

```yaml
---
name: example-skill
description: 何时使用该 Skill
---
```

System Prompt（系统提示词）只注入 Skill 的名称、描述和位置，不注入完整正文。模型判断任务匹配后调用 `skill` 工具加载内容。

## Skill 加载

加载顺序：

1. 首次调用只传 `name`，读取 `SKILL.md`。
2. Skill 正文进入当前上下文。
3. 需要 Reference 时再次传 `name + reference`。
4. Reference 路径通过真实路径校验，禁止逃逸 Skill 目录。

Skill 加载状态在 Session 切换、新建或清理时重置。

Frontmatter 中未被注册表解析的字段不会自动形成执行权限。真正的权限仍由对应 Tool 控制。

## Tavily 扩展

当前扩展包含：

- `tavily-cli`
- `tavily-search`
- `tavily-extract`
- `tavily-map`
- `tavily-crawl`
- `tavily-research`

这些 Skill 指导 Agent 通过 Bash 调用外部 `tvly` CLI（命令行工具）。Vivlos 当前不负责 CLI 安装、登录、配额或可用性检测。

## 添加 Tool

新增 Tool 的最小步骤：

1. 定义清晰、严格的参数 Schema。
2. 在适配层把参数转换成领域命令。
3. 执行失败时抛 `ToolError`。
4. 返回简洁的模型内容和必要的结构化 details。
5. 选择默认并行或顺序执行模式。
6. 注册到对应 Tool Registry。

Tool 描述中不要复制完整项目文档，存储、安全和业务规则也不要散落到界面层。

## 添加 Skill

新增 Skill 时建议：

1. 创建独立目录和 `SKILL.md`。
2. 提供准确的 `name` 与触发描述。
3. 正文只写完成该类任务所需的工作流。
4. 大型参考资料放入 Skill 自身 `references/`。
5. 明确实际依赖的 Tool、CLI、凭证和安全边界。
