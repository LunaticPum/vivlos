# 工具与技能

Tool 提供可执行能力，Skill 提供按需加载的专业操作指引。两者职责不同：Skill 本身不执行任务，最终操作仍由 Tool 完成。

## Tool 分类

### Builtin Tools

| Tool | 作用 |
| --- | --- |
| `read` | 读取文件 |
| `write` | 新建或完整写入文件 |
| `bash` | 执行 Shell 命令 |
| `ls` | 列出目录 |
| `grep` | 搜索文件内容 |
| `find` | 查找文件 |
| `skill` | 加载 Skill 正文或 Reference |

### Advanced Tools

| Tool | 作用 |
| --- | --- |
| `memory` | 管理当前 Session 的 L1 Memory |
| `todo_*` | 管理当前 Session 的 Todo List |
| `task` | 管理跨 Session Task |
| `offer_choice` | 等待用户选择 |

Tool Registry 按名称注册工具。同名 Tool 后注册时覆盖前一个定义，最终列表注入 Agent Context。

## Tool Schema

Tool 使用 TypeBox 描述参数：

- 静态结构由 `Type.Object`、`Type.Array`、`Type.Union` 等表达。
- `additionalProperties: false` 防止模型传入未声明字段。
- 动态业务约束在 Tool Adapter 或 Domain 层检查。
- Schema Description 应说明参数含义，不承载整套工作流文档。

## 参数准备

`prepareArguments` 发生在 Schema 校验之前，只用于窄范围兼容：

- Skill Tool 丢弃部分模型误传的无关字段。
- Todo 将合法的字符串化 Item 数组恢复成真实数组。

损坏参数不使用正则或宽松解析器猜测修复。准备或校验失败会生成明确 Tool Error，由模型下一轮自行修正。

## 执行模式

pi 支持并行和顺序执行：

- 默认 Tool 可以与同批独立调用并行。
- 任一 Tool 声明 `sequential` 时，整批按顺序执行。
- Todo 使用 sequential，避免同一 List 的并发写入。
- Offer Choice 使用 sequential，避免多个交互等待重叠。

多个独立操作应在同一个 assistant response 中发出；存在结果依赖时才拆成多个 ReAct step。

## 结果与错误

成功 Tool 返回：

- `content`：提供给模型的文本或结构化结果。
- `details`：提供给 UI、事件和日志的结构化信息。
- 可选 `terminate`：整批结果都要求终止时，不再请求下一轮模型。

执行失败必须抛出 `ToolError`。pi 会生成 `isError: true` 的 Tool Result，并将其回灌模型。

只有成功 Tool Result 才能作为“操作已完成”的依据。Thinking、普通文本或错误内容都不能证明写盘、命令或状态更新成功。

## Bash Tool

Bash 在 Windows 优先使用 Git Bash，支持：

- 超时控制。
- AbortSignal。
- 进程树终止。
- stdout/stderr 输出上限。
- 通配权限规则。

权限规则位于 `.vivlos/config.json`，按配置顺序匹配，并以最后命中的规则为准。

> [!WARNING]
> Bash 不是 Sandbox，当前没有逐次确认 UI。宽泛的后置 `allow` 规则可能覆盖前面的 `deny`，配置时必须检查规则顺序。

文件工具同样允许绝对路径，当前没有统一 Workspace containment。

## Skill 发现

启动时递归扫描内置和扩展目录下的 `SKILL.md`。YAML Frontmatter 至少包含：

```yaml
---
name: example-skill
description: 何时使用该 Skill
---
```

System Prompt 只注入 Skill 的名称、描述和位置，不注入完整正文。模型判断任务匹配后调用 `skill` Tool 加载内容。

## Skill 加载

加载顺序：

1. 首次调用只传 `name`，读取 `SKILL.md`。
2. Skill 正文进入当前上下文。
3. 需要 Reference 时再次传 `name + reference`。
4. Reference 路径通过 Realpath 校验，禁止逃逸 Skill 目录。

Skill 加载状态在 Session 切换、新建或清理时重置。

Frontmatter 中未被 Registry 解析的字段不会自动形成执行权限。真正的权限仍由对应 Tool 控制。

## Tavily 扩展

当前扩展包含：

- `tavily-cli`
- `tavily-search`
- `tavily-extract`
- `tavily-map`
- `tavily-crawl`
- `tavily-research`

这些 Skill 指导 Agent 通过 Bash 调用外部 `tvly` CLI。Vivlos 当前不负责 CLI 安装、登录、配额或可用性检测。

## 添加 Tool

新增 Tool 的最小步骤：

1. 定义清晰、严格的参数 Schema。
2. 在 Adapter 中把参数转换成领域命令。
3. 执行失败时抛 `ToolError`。
4. 返回简洁的模型内容和必要的结构化 Details。
5. 选择默认并行或 sequential 模式。
6. 注册到对应 Tool Registry。

不要在 Tool Description 中复制完整项目文档，也不要把存储、安全和业务规则散落到 UI。

## 添加 Skill

新增 Skill 时应：

1. 创建独立目录和 `SKILL.md`。
2. 提供准确的 `name` 与触发描述。
3. 正文只写完成该类任务所需的工作流。
4. 大型参考资料放入 Skill 自身 `references/`。
5. 明确实际依赖的 Tool、CLI、凭证和安全边界。
