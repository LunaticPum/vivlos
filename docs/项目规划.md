## 🧱 第一阶段：核心框架（MVP）

### 1.1 LLM 接入层 — 最底层基础

**核心职责：** 连接不同的 LLM 提供商，统一 API 调用接口。

| 组件 | 说明 |
|------|------|
| `ModelRegistry` | 模型注册表，管理可用模型列表 |
| `AuthStorage` | API Key 管理（环境变量 → 配置文件 → 运行时覆盖） |
| `Provider` 抽象 | 各厂商的适配器（Anthropic / OpenAI / Google 等） |

**你需要做的事：**

1. 定义统一 `LLMProvider` 接口
    ```typescript
    interface LLMProvider {
      chat(options: ChatOptions): AsyncIterable<ChatEvent>
    }
    interface ChatOptions {
      messages: Message[]
      tools?: ToolDefinition[]
      signal?: AbortSignal
    }
    type ChatEvent =
      | { type: "text_delta"; delta: string }
      | { type: "thinking_delta"; delta: string }
      | { type: "tool_calls"; calls: ToolCall[] }
      | { type: "done"; usage?: Usage }
      | { type: "error"; error: Error }
    ```

2. 先实现 1-2 个 Provider（推荐 OpenAI API 格式，兼容性最广）

3. 支持 streaming 和非 streaming 两种调用模式

4. 实现 API Key 的优先级解析：
    ```
    运行时覆盖 > auth.json 存储 > 环境变量 > 自定义 fallback
    ```

**关键设计决策：**
- 是否需要支持 tool calling（Function Calling）？→ **强烈建议支持**，这是 agent 的核心能力
- 消息格式：统一使用 OpenAI 的 message 格式作为内部标准（兼容性最好）

### 1.2 Agent 核心循环

**核心职责：** 管理「用户输入 → LLM 响应 → 工具调用 → 继续循环」的核心流程。

```
用户输入
  ↓
构建 system prompt + 消息历史
  ↓
调用 LLM (streaming)
  ├─ 文本响应 → 展示给用户
  ├─ thinking 内容 → 可选展示
  └─ tool_calls → 执行工具 → 结果送回 LLM → 继续
  ↓
一轮结束 / 用户打断
```

**核心类：AgentSession**

```typescript
interface AgentSession {
  // 发送 prompt 并等待完成
  prompt(text: string, options?: PromptOptions): Promise<void>

  // 流式处理中插入消息
  steer(text: string): Promise<void>
  followUp(text: string): Promise<void>

  // 订阅事件（返回取消订阅函数）
  subscribe(listener: (event: AgentSessionEvent) => void): () => void

  // 模型控制
  setModel(model: Model): Promise<void>
  setThinkingLevel(level: ThinkingLevel): void

  // 状态访问
  agent: Agent
  messages: AgentMessage[]
  isStreaming: boolean

  // 中止当前操作
  abort(): Promise<void>

  // 清理
  dispose(): void
}
```

**事件系统：**

| 事件类型 | 触发时机 |
|----------|----------|
| `message_start` | 新消息开始 |
| `message_update` | 流式文本增量 |
| `message_end` | 消息完成 |
| `tool_execution_start` | 工具开始执行 |
| `tool_execution_update` | 工具输出流式更新 |
| `tool_execution_end` | 工具执行完成 |
| `turn_start` / `turn_end` | 每一轮 LLM 往返 |
| `agent_start` / `agent_end` | 一次用户 prompt 的开始和结束 |
| `compaction_start` / `compaction_end` | 上下文压缩 |

**你需要做的事：**

1. 实现 Agent 循环（loop）：LLM 返回 tool_calls 就继续调用
2. 支持并行 tool calling（多个工具同时执行）
3. 实现 streaming 事件发射器
4. 支持 abort/cancel（通过 AbortController）
5. 消息队列（steer / followUp 区分中途干预和结束后补充）

### 1.3 工具系统

**核心职责：** 定义模型可调用的函数。

**内置工具（参考 pi）：**

| 工具 | 说明 | 参数 |
|------|------|------|
| `read` | 读取文件内容，支持 offset/limit | `path`, `offset?`, `limit?` |
| `write` | 创建/覆盖文件 | `path`, `content` |
| `edit` | 精确文本替换编辑 | `path`, `edits[]`（oldText + newText） |
| `bash` | 执行 shell 命令 | `command`, `timeout?` |
| `grep` | 搜索文件内容 | `pattern`, `path?`, `include?` |
| `find` | 查找文件 | `pattern`, `path?` |
| `ls` | 列出目录 | `path?` |

**工具定义接口：**

```typescript
import { Type } from "typebox"

interface ToolDefinition {
  name: string
  label?: string        // 展示用名称
  description: string   // 给 LLM 看的描述
  parameters: ReturnType<typeof Type.Object>  // JSON Schema
  promptSnippet?: string     // 工具列表中的一行描述
  promptGuidelines?: string[] // 附加到 Guidelines 节的说明
  
  execute(
    toolCallId: string,
    params: Record<string, unknown>,
    signal: AbortSignal,
    onUpdate?: (partial: ToolResult) => void,
    ctx: ExtensionContext
  ): Promise<ToolResult>
}
```

**辅助函数：**

```typescript
// 更方便的定义方式
const myTool = defineTool({
  name: "my_tool",
  label: "My Tool",
  description: "Does something useful",
  parameters: Type.Object({
    input: Type.String({ description: "Input value" }),
  }),
  execute: async (_toolCallId, params) => ({
    content: [{ type: "text", text: `Result: ${params.input}` }],
    details: {},
  }),
})
```

**你需要做的事：**

1. 定义 `Tool` 接口和 `defineTool()` 辅助函数
2. 实现 `read`、`write`、`edit`、`bash` 这四个核心工具
3. 支持工具执行的 streaming 输出
4. 支持 `--tools` 白名单和 `--exclude-tools` 黑名单
5. 支持自定义工具注册（`pi.registerTool()`）

### 1.4 会话管理

**核心职责：** 持久化对话历史，支持分支和恢复。

**JSONL 条目格式：**

```typescript
interface SessionEntry {
  id: string          // 唯一 ID
  parentId?: string   // 父条目 ID（形成树结构）
  role?: "user" | "assistant" | "tool"
  content: ContentBlock[]
  timestamp: number
  // ...其他元数据
}
```

**SessionManager API：**

```typescript
interface SessionManager {
  // 工厂方法
  static inMemory(): SessionManager
  static create(cwd: string): SessionManager       // 新建持久化
  static continueRecent(cwd: string): SessionManager // 继续最近
  static open(path: string): SessionManager         // 打开指定
  static list(cwd: string): SessionSummary[]        // 列出会话
  static listAll(cwd: string): SessionSummary[]

  // 树导航
  getEntries(): SessionEntry[]
  getTree(): TreeNode
  getPath(): SessionEntry[]
  getLeafEntry(): SessionEntry
  getEntry(id: string): SessionEntry | undefined
  getChildren(id: string): SessionEntry[]

  // 分支操作
  branch(entryId: string): void
  createBranchedSession(leafId: string): string  // 提取路径为新文件

  // 标签
  getLabel(id: string): string | undefined
  appendLabelChange(id: string, label: string): void
}
```

**你需要做的事：**

1. 定义 JSONL 文件格式（header + entries）
2. 实现 SessionManager 的 CRUD 操作
3. 实现树结构导航（id/parentId 链表）
4. 支持分支（branch）操作
5. 实现自动保存（每次修改后持久化）

### 2.2 扩展系统

**核心职责：** 允许第三方 TypeScript 模块注入自定义行为。

**扩展可以做的事：**

1. **注册自定义工具** — LLM 可以调用的新函数
2. **监听事件钩子** — 在 Agent 生命周期各阶段介入
3. **注册命令** — 如 `/mycommand`
4. **阻塞/修改工具调用** — 权限门控、参数变换
5. **修改工具结果** — 结果后处理
6. **添加 UI 组件** — 状态栏、widget、自定义 footer

**完整事件生命周期：**

```
pi 启动
  │
  ├─► project_trust（用户/全局扩展和 CLI -e 扩展）
  ├─► session_start { reason: "startup" }
  └─► resources_discover { reason: "startup" }
      │
      ▼
用户发送 prompt ─────────────────────────────────────────┐
  │                                                        │
  ├─►（扩展命令先检查，命中直接执行）                          │
  ├─► input（可拦截、转换、或处理）                          │
  ├─►（技能/模板展开）                                      │
  ├─► before_agent_start（可注入消息、修改 system prompt）   │
  ├─► agent_start                                          │
  ├─► message_start / message_update / message_end         │
  │                                                        │
  │   ┌─── turn（循环执行 LLM 调工具） ───┐                  │
  │   │                                    │               │
  │   ├─► turn_start                       │               │
  │   ├─► context（可修改消息历史）          │               │
  │   ├─► before_provider_request          │               │
  │   │                                    │               │
  │   │   LLM 响应，可能调用工具：            │               │
  │   │     ├─► tool_execution_start        │               │
  │   │     ├─► tool_call（可阻塞）          │               │
  │   │     ├─► tool_execution_update        │               │
  │   │     ├─► tool_result（可修改结果）     │               │
  │   │     └─► tool_execution_end           │               │
  │   │                                    │               │
  │   └─► turn_end                          │               │
  │                                                        │
  └─► agent_end                                            │
                                                           │
/new /resume 等会话切换
  ├─► session_before_switch
  ├─► session_shutdown
  ├─► session_start { reason: "new" | "resume" }
  └─► resources_discover

/compact 压缩
  ├─► session_before_compact
  └─► session_compact

退出
  └─► session_shutdown
```

**Extension API：**

```typescript
interface ExtensionAPI {
  // 注册事件监听
  on<K extends EventName>(event: K, handler: EventHandler<K>): void

  // 注册工具（可动态注册，立即生效）
  registerTool(definition: ToolDefinition): void

  // 注册命令
  registerCommand(name: string, def: CommandDefinition): void

  // 注册快捷键
  registerShortcut(key: string, def: ShortcutDefinition): void

  // 注册 CLI flag
  registerFlag(name: string, def: FlagDefinition): void

  // 注册 Provider（动态添加 LLM 提供商）
  registerProvider(name: string, config: ProviderConfig): void

  // 发送消息到会话
  sendMessage(msg: CustomMessage, options?: SendOptions): void

  // 发送用户消息（触发一轮 agent 处理）
  sendUserMessage(content: Content[], options?: SendOptions): void

  // 获取所有注册的工具
  getAllTools(): ToolDefinition[]

  // 设置当前启用的工具列表
  setActiveTools(toolNames: string[]): void
}
```

**ExtensionContext（事件处理器的上下文）：**

```typescript
interface ExtensionContext {
  ui: {
    notify(msg: string, level: "info" | "warn" | "error"): void
    confirm(title: string, msg: string): Promise<boolean>
    select(title: string, options: string[]): Promise<string | undefined>
    input(title: string, placeholder?: string): Promise<string | undefined>
    setStatus(id: string, text: string): void
    setWidget(id: string, lines: string[], position?: "above" | "below"): void
  }

  mode: "tui" | "rpc" | "json" | "print"
  hasUI: boolean
  cwd: string
  signal?: AbortSignal

  sessionManager: SessionManager
  modelRegistry: ModelRegistry
  model?: Model

  isIdle(): boolean
  abort(): void
  getContextUsage(): ContextUsage | undefined
  getSystemPrompt(): string
  compact(options?: CompactOptions): void
  shutdown(): void
}
```

**你需要做的事：**

1. 定义 `ExtensionAPI` 和 `ExtensionContext` 完整类型
2. 使用 jiti 或 tsx 加载 TypeScript 文件（无需编译）
3. 实现事件总线（EventBus）
4. 实现事件处理器的链式处理（如 `tool_result` 可链式修改）
5. 实现 UI 协议（兼容 TUI 和 RPC 模式）

### 2.3 技能系统

**核心职责：** 按需加载的指令包，遵循 [Agent Skills 标准](https://agentskills.io)。

**技能目录结构：**

```
my-skill/
├── SKILL.md              ← 必需：frontmatter + 使用说明
├── scripts/              ← 辅助脚本
│   └── process.sh
├── references/           ← 参考文档（按需加载）
│   └── api-reference.md
└── assets/
    └── template.json
```

**SKILL.md 格式：**

```markdown
---
name: my-skill
description: What this skill does and when to use it. Be specific.
---

# My Skill

## Setup

Run once before first use:
```bash
cd /path/to/skill && npm install
```

## Usage

```bash
./scripts/process.sh <input>
```
```

**Frontmatter 字段：**

| 字段 | 必需 | 说明 |
|------|------|------|
| `name` | 是 | 最大 64 字符，小写字母、数字、连字符 |
| `description` | 是 | 最大 1024 字符，说明何时使用 |
| `license` | 否 | 许可证 |
| `compatibility` | 否 | 环境要求 |
| `allowed-tools` | 否 | 预批准的工具列表 |
| `disable-model-invocation` | 否 | true 时对 LLM 隐藏，需手动 `/skill:name` |

**工作流程：**

1. 启动时扫描技能目录，提取 name + description
2. 技能列表以 XML 格式注入 system prompt
3. LLM 根据描述决定是否加载完整 SKILL.md
4. 用户也可通过 `/skill:name` 手动触发

**你需要做的事：**

1. 实现 SKILL.md 解析（YAML frontmatter + markdown）
2. 将技能信息以标准 XML 格式注入 system prompt
3. 支持多层目录递归发现
4. 实现 `/skill:name` 命令
5. 支持技能命令参数（`/skill:name arg1 arg2`）

### 2.4 提示模板

**核心职责：** 可复用的 Markdown 片段，通过 `/name` 触发。

**格式：**

```markdown
---
description: Review staged git changes
argument-hint: "<PR-URL>"
---
Review the staged changes. Focus on bugs and security issues.
```

- 文件名（不含 `.md`）即命令名
- 支持参数展开：`$1`, `$2`, `$@`, `$ARGUMENTS`
- 支持默认值：`${1:-default}`
- 支持切片：`${@:N}`, `${@:N:L}`
- `description` 可选，缺省则取首行非空内容
- `argument-hint` 可选，在自动补全中展示参数提示

**你需要做的事：**

1. 扫描 `prompts/` 目录（非递归）
2. 实现参数展开引擎
3. 集成到命令补全系统
4. 支持 settings 和 CLI 指定

> 以下所有决策已对齐 pi 的设计，开发时按此执行，无需再纠结技术选型。

| 问题 | pi 的选择 | 说明 |
|------|-----------|------|
| 开发语言 | **TypeScript** | 类型安全，pi 使用 jiti 实现无需编译即可运行 TS |

| TUI 框架 | **自建**（参照 `@earendil-works/pi-tui`） | blessed 风格的组件树：Container, Box, Text, EditorComponent |
| Agent 循环 | **事件驱动**（同步 EventEmitter + 事件流） | `turn_start → tool_call → tool_result → turn_end` 链式事件 |
| 消息格式 | **自定义格式**（兼容 OpenAI message 结构） | `{ role, content: [{type, text}], tool_calls?, tool_call_id? }` |
| 会话格式 | **JSONL 树结构**（id/parentId） | 每行一个 JSON 条目，支持原地分支，不创建新文件 |
| 工具 Schema | **typebox** | 编译时类型安全 + 运行时校验，比 JSON Schema 更易用 |
| 扩展加载 | **jiti**（TypeScript 即时代码加载） | 无需编译，既支持单文件也支持目录 + package.json |
| 配置层级 | **全局 + 项目两层浅合并** | `~/.pi/agent/settings.json`（全局）→ `.pi/settings.json`（项目覆盖） |
| 技能标准 | **Agent Skills 标准** | 遵循 https://agentskills.io，跨工具兼容 |
| 模型默认值 | **settings → 第一个可用模型** | 优先级：settings.json 配置 > `--model` CLI flag > 第一个可用 |
| 终端平台 | **跨平台支持** | Windows / macOS / Linux，通过 `node:path` 和条件逻辑处理差异 |
| 上下文文件 | **AGENTS.md / CLAUDE.md** | 从 cwd 向上递归查找，全部拼接 |

| Session 存储 | **`~/.pi/agent/sessions/`** | 按工作目录组织，`--session-dir` 可自定义 |

## 💡 最小起步建议

1. **先别碰 TUI** — 用 Print 模式（`-p`）走通整个 Agent 循环
2. **先不要做扩展系统** — 把所有代码写在一个项目里
3. **先只支持一家 LLM** — OpenAI（兼容性最广），跑通后再抽象
4. **先用 InMemory 会话** — 不急着做 JSONL 持久化
5. **核心就三个循环**：`发消息 → 收响应 → 如有 tool_call 继续循环`

### 最小可运行版目录结构

```
my-agent/
├── src/
│   ├── index.ts              # CLI 入口
│   ├── llm/
│   │   ├── provider.ts       # LLM Provider 接口
│   │   └── openai.ts         # OpenAI 实现
│   ├── agent/
│   │   ├── session.ts        # AgentSession 核心
│   │   └── loop.ts           # Agent 循环
│   ├── tools/
│   │   ├── registry.ts       # 工具注册表
│   │   ├── read.ts
│   │   ├── write.ts
│   │   ├── edit.ts
│   │   └── bash.ts
│   └── types/
│       └── index.ts          # 通用类型定义
├── package.json
└── tsconfig.json
```

这个最小版本大约 **500-800 行核心代码**，可以在 1-2 周内完成。
