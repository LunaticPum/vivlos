# 使用指南

Vivlos 当前以源码方式运行。启动命令所在目录会成为 Workspace，本地状态也会保存在该目录中。

## 环境要求

- Bun 1.3 或更高版本
- 支持现代终端控制能力的终端程序
- 至少一个可用的 LLM Provider API Key

## 获取与启动

```bash
git clone https://github.com/LunaticPum/vivlos.git
cd vivlos
bun install
```

复制环境变量模板：

```powershell
Copy-Item .env.example .env
```

或在 Bash 中执行：

```bash
cp .env.example .env
```

填写默认模型和对应的 API Key：

```dotenv
DEEPSEEK_API_KEY=your-api-key
VIVLOS_DEFAULT_PROVIDER=deepseek
VIVLOS_DEFAULT_MODEL=your-model-id
```

启动 Vivlos：

```bash
bun run dev
```

## 模型配置

Vivlos 使用 pi-ai 提供内置 Provider 和 Model 目录。可用模型取决于当前 pi-ai 版本及本地凭证。

在 TUI 中可以：

- 使用 `Ctrl+P` 或 `/providers` 切换 Provider。
- 使用 `Ctrl+L` 或 `/models` 切换当前 Provider 的 Model。
- 为已有 Provider 输入 API Key。
- 添加 OpenAI Compatible 或 Anthropic Compatible 服务。

新建自定义 Provider 时，Vivlos 会发送一个短请求验证连接。自定义地址、模型和凭证会保存在当前 Workspace 的 SQLite 中。

> [!WARNING]
> 当前 Credential Store 是本地持久化，没有额外的应用层加密。请保护 `.vivlos/vivlos.db`，不要提交或共享该文件。

## 配置优先级

首次启动会读取 `.env` 中的默认 Provider 和 Model，并写入 SQLite。之后保存过的 SQLite 配置优先于 `.env`，修改环境变量不会自动覆盖已有选择。

`<workspace>/.vivlos/config.json` 用于重试、上下文压缩、Memory 容量和 Bash 权限等运行参数。

## 基本操作

| 操作 | 快捷键或命令 |
| --- | --- |
| 发送消息 | `Enter` |
| 输入换行 | `Ctrl+Enter` |
| 浏览最近输入 | 输入框首尾行使用 `Up` / `Down` |
| 打开帮助 | `Ctrl+O` 或 `/help` |
| 查看会话 | `/sessions` |
| 新建会话 | `/new` |
| 重命名会话 | `/rename` |
| 手动压缩上下文 | `/compact` |
| 清空当前界面 | `/clear` |
| 中止正在运行的请求 | `Ctrl+C` |
| 退出 | 空闲时在 3 秒内连续按两次 `Ctrl+C` |

`/clear` 只清空当前界面，不删除 `history.jsonl`，也不会移除下一次请求使用的会话历史。

## Workspace 与本地数据

Vivlos 默认在当前工作目录创建：

```text
.vivlos/
├── config.json
├── vivlos.db
├── sessions/
│   └── <session-id>/
│       ├── history.jsonl
│       ├── memory.md
│       ├── user.md
│       ├── memory-events.jsonl
│       └── todos.json
├── tasks/
└── temp/
```

- Session、L1 Memory 和 Todo 以 Session 为边界。
- Task 保存在 `.vivlos/tasks/`，可以跨 Session 使用。
- Provider、Model、Credential 和自定义服务配置保存在 `vivlos.db`。
- `.vivlos/` 和 `.env` 不应提交到版本控制。

## Tavily 扩展

Vivlos 内置 Tavily Skill，但实际搜索通过外部 `tvly` CLI 执行。使用前需要自行安装并登录 Tavily CLI，或配置 `TAVILY_API_KEY`。

Skill 只向 Agent 提供操作指引，最终命令仍通过 Bash Tool 执行。

## 安全边界

Vivlos 当前不是 Sandbox：

- Bash 可以启动本机进程。
- 文件工具可以接收绝对路径。
- Bash 权限按 `.vivlos/config.json` 中的通配规则判断。
- 当前没有逐次执行确认弹窗。

请在可信目录和可恢复环境中运行，不要将 Vivlos 直接用于不受信任的输入或生产主机。

## 常见问题

### 启动前提示找不到模型

确认 `.env` 或 SQLite 中保存的 Provider 和 Model 仍存在于当前 pi-ai 模型目录。必要时删除或修正 Workspace 的本地模型配置。

### 修改 `.env` 后没有生效

已保存的 SQLite 配置优先。进入 Provider/Model 选择界面重新选择，或清理对应 Workspace 的本地配置。

### Memory 没有出现在新 Session

当前已实现的 L1 Memory 是 Session-local，不会自动继承到新 Session。跨 Session 检索与外部 Memory Provider 仍处于设计阶段。
