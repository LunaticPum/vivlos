# 使用指南

Vivlos 当前以源码方式运行。启动命令所在目录会成为 Workspace（工作目录），本地状态也会保存在该目录中。

## 环境要求

- Bun 1.3 或更高版本
- 支持现代终端控制能力的终端程序
- 至少一个可用的 LLM Provider API Key（模型服务商的接口凭证）

## 获取与启动

```bash
git clone https://github.com/LunaticPum/vivlos.git
cd vivlos
bun install
```

复制环境变量模板：

```powershell
Copy-Item .env.example .env
```

或在 Bash 中执行：

```bash
cp .env.example .env
```

填写默认模型和对应的 API Key：

```dotenv
DEEPSEEK_API_KEY=your-api-key
VIVLOS_DEFAULT_PROVIDER=deepseek
VIVLOS_DEFAULT_MODEL=your-model-id
```

启动 Vivlos：

```bash
bun run dev
```

## 模型配置

Vivlos 使用 pi-ai（模型接入库）提供内置 Provider（模型服务商）和 Model（模型）目录。可用模型取决于当前 pi-ai 版本及本地凭证。

在 TUI（终端界面）中可以：

- 使用 `Ctrl+P` 或 `/providers` 切换 Provider。
- 使用 `Ctrl+L` 或 `/models` 打开模型选择弹窗。
- 为已有 Provider 输入 API Key。
- 添加 OpenAI Compatible 或 Anthropic Compatible（兼容接口）服务。

模型选择弹窗支持：

- **键入筛选**：打开后直接敲字符过滤模型列表，Backspace 删除，Esc 先清空筛选再关闭。
- **能力标签**：每个模型右侧标注 `[文本]` 或 `[文本,视觉]`（亮色区分），再右侧为上下文窗口大小。
- **指定视觉模型**：双击 `g` 将支持视觉的模型指定为图片解析专用模型（行尾显示 `◉`，再双击取消）。未指定时图片解析使用当前主模型。

新建自定义 Provider 时，Vivlos 会发送一个短请求验证连接。自定义地址、模型和凭证会保存在当前 Workspace 的 SQLite（嵌入式数据库）中；自定义模型可勾选"视觉"开关声明其支持图片输入。

> [!WARNING]
> 当前 Credential Store（凭证存储）是本地持久化，没有额外的应用层加密。请保护 `.vivlos/vivlos.db`，不要提交或共享该文件。
> 模型弹窗列出的是 Provider 目录中的全部模型，账号实际可用的范围取决于订阅或购买情况。

## 配置优先级

首次启动会读取 `.env` 中的默认 Provider 和 Model，并写入 SQLite。之后保存过的 SQLite 配置优先于 `.env`，修改环境变量不会自动覆盖已有选择。

`<workspace>/.vivlos/config.json` 用于重试、上下文压缩、Memory 容量和 Bash 权限等运行参数。

## 基本操作

| 操作 | 快捷键或命令 |
| --- | --- |
| 发送消息 | `Enter` |
| 输入换行 | `Ctrl+Enter` |
| 浏览最近输入 | 输入框首尾行使用 `Up` / `Down` |
| 打开帮助 | `Ctrl+O` 或 `/help` |
| 模型选择 | `Ctrl+L` 或 `/models` |
| 供应商选择 | `Ctrl+P` 或 `/providers` |
| 粘贴剪贴板截图 | `Ctrl+G`（Windows） |
| 查看会话 | `/sessions` |
| 新建会话 | `/new` |
| 重命名会话 | `/rename` |
| 手动压缩上下文 | `/compact` |
| 清空当前界面 | `/clear` |
| 中止正在运行的请求 | `Ctrl+C` |
| 退出 | 空闲时在 3 秒内连续按两次 `Ctrl+C` |

`/clear` 只清空当前界面，不删除 `history.jsonl`，也不会移除下一次请求使用的会话历史。

## 图片识别

Vivlos 支持向多模态模型发送图片。三种附加图片的方式：

| 方式 | 说明 |
| --- | --- |
| 拖入终端 | 把图片文件拖进终端窗口（终端会将拖入转换为路径粘贴，自动识别为附件） |
| 粘贴路径 | 直接粘贴图片文件路径（支持引号包裹、`file://` 前缀、多行多文件） |
| `Ctrl+G` | 读取剪贴板中的截图位图（Windows，配合 Win+Shift+S / PrintScreen 使用） |

附件规则：

- 附件在输入栏上方以 `[文件名]` 展示，输入为空时按 Backspace 逐个移除。
- 可以先输入文字说明再发送，也可以直接发送。
- 图片格式支持 png / jpg / jpeg / gif / webp，单张上限 4MB。
- `Ctrl+G` 读取剪贴板约需 1-2 秒（PowerShell 冷启动开销），期间会显示提示；同一张截图重复读取只会生成一份临时文件。
- 剪贴板截图保存在 `.vivlos/temp/`，启动时自动清理。

视觉模型解析顺序：

1. 已在模型弹窗指定的视觉模型（双击 `g` 指定，行尾 `◉` 标记）。
2. 未指定时使用当前主模型（需支持图片输入）。
3. 两者都不可用时，通知栏提示并拒绝发送。

发送图片且未附文字说明时，Agent 会先通过交互式选项询问解析方式（快速描述 / 详细描述 / 提取图中文字 / 自由分析）；附有文字说明时直接按说明执行。含图片的整轮对话使用视觉模型运行。

## Workspace 与本地数据

Vivlos 默认在当前工作目录创建：

```text
.vivlos/
├── config.json
├── vivlos.db
├── memory.db
├── sessions/
│   └── <session-id>/
│       ├── history.jsonl
│       ├── memory.md
│       ├── user.md
│       ├── memory-events.jsonl
│       └── todos.json
└── temp/
```

- Session（会话）、L1 Memory（会话记忆）和 Todo（待办）以 Session 为边界。
- 子任务委派（Delegation）的子代理为内存态，不落盘。
- Provider、Model、Credential（凭证）和自定义服务配置保存在 `vivlos.db`。
- `memory.db` 是 L2 历史会话索引，可删除重建。
- `.vivlos/` 和 `.env` 不应提交到版本控制。

## Tavily 扩展

Vivlos 内置 Tavily Skill（搜索技能），但实际搜索通过外部 `tvly` CLI（命令行工具）执行。使用前需要自行安装并登录 Tavily CLI，或配置 `TAVILY_API_KEY`。

Skill 只向 Agent（智能体）提供操作指引，最终命令仍通过 Bash Tool（命令行工具）执行。

## 安全边界

Vivlos 当前不是 Sandbox（沙箱）：

- Bash 可以启动本机进程。
- 文件工具可以接收绝对路径。
- Bash 权限按 `.vivlos/config.json` 中的通配规则判断。
- 当前没有逐次执行确认弹窗。

请在可信目录和可恢复环境中运行，不要将 Vivlos 直接用于不受信任的输入或生产主机。

## 常见问题

### 启动前提示找不到模型

确认 `.env` 或 SQLite 中保存的 Provider 和 Model 仍存在于当前 pi-ai 模型目录。必要时删除或修正 Workspace 的本地模型配置。

### 修改 `.env` 后没有生效

已保存的 SQLite 配置优先。进入 Provider/Model 选择界面重新选择，或清理对应 Workspace 的本地配置。

### Memory 没有出现在新 Session

当前已实现的 L1 Memory 是 Session-local（会话内有效），不会自动继承到新 Session。跨 Session 的历史细节可以通过 `session_search`（L2 历史检索）找回；外部 Memory Provider（L3）仍处于设计阶段。
